### 5. refactor(notifications): modernize UI with dismissal persistence

**Redesign notification bars for a cleaner, more professional appearance:**

- Reduce padding (py-3 → py-2.5, px-4)
- Replace full border with accent left border (border-l-4)
- Remove shadow and tighten spacing for minimal design
- Adjust icon sizing and line height for better visual hierarchy
- Replace yellow with professional amber color scheme

**Implement dismissal persistence with localStorage TTL:**

- Add notification dismissal tracking in `storage.ts` with 15-minute TTL
- Track dismissed notifications per-message using deterministic hashing
- Implement `useSyncExternalStore` for SSR-safe hydration
- Add auto-restore timer that clears dismissal after TTL expires
- Listeners enable cross-tab synchronization

**Add text-only dismiss button to warning & alert notifications:**

- Style as clean text-only button (no outline/border)
- Exclude dismiss button from info notifications
- Hover effect with opacity transition
- Conditional rendering based on notification type

Fixes dismissal state persistence and provides users with better control over non-critical notifications while maintaining info notifications as persistent.

### 6. fix(tm-graph): enable year override for testing and fix transition highlighting

**Centralize year derivation with TEST_OVERRIDE_YEAR constant:**

- Add module-level override constant in `tm-graph.ts` (default: null)
- Modify `getCurrentYear()` to return override or system year
- Ensures all consumers (header, cells, badges) use same year

**Fix golden square highlighting for manual year testing:**

- Previously, manual year overrides only affected header label, not cell highlighting
- Root cause: `getTMStatus()` and `isTransitionYear` checks called `getCurrentYear()` independently after override was removed
- Solution: Single source of truth via `TEST_OVERRIDE_YEAR` ensures all functions return consistent values
- Now header, golden borders, and badge badges all sync correctly

**Add developer documentation:**

- Comment explains how to test future years by setting `TEST_OVERRIDE_YEAR`
- Clear instructions for toggling between test and production modes
- No hardcoded years; all computed live from override or system clock

Enables reliable testing of the T/M (Textbook/Module) transition graph across multiple years without manual component edits.
